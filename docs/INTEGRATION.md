# Grok 与 pi 接入记录

记录日期：2026-09-22。当前交付为本机通信接入版，覆盖真实 Grok ↔ pi 会话、统一入口和必要的消息控制。Codex 按用户要求暂缓；本记录不把完整 [SPEC](../SPEC.md) 标为已实现。

## 1. 已验证的结果

在用户授权的 `deepseek-v4-flash` 配置下，两种真实 harness 均能主动发信、接收同伴消息、读取显式共享材料并回复。最终工具隔离配置下完成了两个发起方向，成功路径共 **6 次 Noah 运行、8 条共享消息**。服务重启后，两边还恢复了原生会话与历史；分别在已派发 prompt 后确认了取消。

Grok 与 pi 使用同一模型服务，但分别运行 Grok CLI 的 Agent 与 Pi 官方 `AgentSession`，拥有各自原生会话和工具循环。这验证跨 harness 通信；不用于证明不同模型讨论一定比单个模型更准确。

| 项目 | 验证环境 |
| --- | --- |
| 操作系统 | 当前用户的 macOS 本机环境 |
| Node.js | 26.7.0；项目要求 24+ |
| Grok | 1.0.40（eb1a2256660d），ACP v1 |
| pi | 官方 `@earendil-works/pi-coding-agent` / `pi-ai` 0.87.0 |
| pi 控制包装 | Noah 自有 `noah.pi-sdk.v1` JSONL，不是 pi CLI 原生 RPC |
| 配置来源 | `~/.grok/config.toml` 中选中模型的 URL、key、backend |
| 真实验证模型 | `deepseek-v4-flash`，`api_backend = responses` |

| 数据位置 | 项目 `.noah`，或 `NOAH_DATA_DIR` 指定目录 |

记录中不保存 API key、完整模型 URL、管理配对 token 或 Agent 工具凭证。原生运行数据目录可能含私有文本，应与脱敏报告区别对待。

### 真实取消

报告：[取消 report.json](../.noah/cancel-smoke/1790070598915/report.json)，时间 `2026-09-22T09:49:58.920Z`。

测试为每个 harness 派发一条长输出请求，在记录 prompt 派发后 250 ms 请求取消。Grok 与 pi 均返回明确 cancelled，Noah 将对应运行终结为 cancelled，而非仅标记界面已点击停止。两次测试各占一次派发。

| Agent | Noah 从请求取消到观察结果 | 结果 |
| --- | --- | --- |
| Grok | 21 ms | cancelled |
| pi | 27 ms | cancelled |

这是当前机器的各一个样本，不是延迟指标，也不能证明模型服务的计费已立即停止。尚未验证执行外部工具期间的取消；当前接入并未开放此类工具。

### 统一界面验收

在最终实现上，通过浏览器创建了「第一次协作：完善 Noah 验收」，显式选择 `deepseek-v4-flash`，上传项目内的合成测试资料 `tests/fixtures/shared-material.txt`，并向 Grok 发起讨论。实际形成 human → Grok → pi → Grok → human，共 3 次完成的运行、4 条共享消息。原始任务和结果保留在当前本地界面；脱敏元数据见 [ui-report.json](../.noah/ui-report.json)。讨论内容是模型提出的候选意见，不作为产品已满足新验收的证据。

界面同时验证了配对、模型下拉、文本上传、过期后消息排队、继续收件箱，以及 390 × 844 窄屏下的对话与控制按钮。Agent / 资料抽屉能显示两个原生会话及材料，也可用 Esc 关闭；测试后已恢复默认浏览器视口。

## 3. 运行与复现

不调用模型的验证：

```sh
npm run doctor
npm test
npm run typecheck
```

2026-09-22 的最终确定性检查结果：**`npm test` 19/19 通过；`npm run typecheck` 通过**。

`doctor` 检查加载配置、Grok ACP 与 pi SDK 握手、会话创建和能力报告，不执行 `session/prompt`。确定性测试覆盖配置映射与脱敏、UTF-8 JSONL、消息幂等、跨任务范围、忙碌排队、额度/暂停竞争、不确定恢复、介入与取消状态，以及 HTTP 配对、来源和重连行为。核心和 HTTP 测试使用受控适配器与临时数据；Pi 恢复测试另直接使用官方 SDK 和真实 worker，但不发出模型请求。

新增的 [Pi 恢复回归](../tests/pi-restore.test.ts) 共四项：

1. 新会话在首个 prompt / assistant 回复之前即可按同一 ID 恢复；首条用户输入也能持久保存。
2. 已绑定文件缺失或为空时失败，不创建替代文件。
3. 原生 ID 不匹配、会话头损坏或绑定字段不完整时失败，保留原文件。
4. 真实 `pi-worker.ts` 启动、关闭、恢复保持同一 ID / 文件；删除已绑定文件后再次启动明确失败，全过程不调用模型。

这些检查验证持久化与接口行为，独立于前文的真实模型通信、历史内容和取消证据。

需要重新验证模型往返时显式运行：

```sh
NOAH_MODEL=deepseek-v4-flash npm run smoke
```

脚本创建独立测试数据目录，不修改已有试用任务。它不自动选择替代供应商，失败就保存失败报告。

基于某次已通过的 smoke 目录复现恢复，以下路径为本次证据所在目录；重跑会增加两次模型调用并更新该目录的恢复报告：

```sh
NOAH_SMOKE_DIR=.noah/smoke/1790070059825 node scripts/resume-smoke.ts
```

重新验证取消会创建独立目录，并发出两次可取消的真实 prompt：

```sh
NOAH_MODEL=deepseek-v4-flash node scripts/cancel-smoke.ts
```

这些是真实推理调用，模型服务可能产生用量。无需为了启动 Noah 而重复运行；已有证据可用于本次接入判断。

## 6. 当前边界与后续重点

- 每个任务固定一个 Grok 和一个 pi，模型别名在创建时选定。没有更改已有原生会话模型、自由成员或同类多实例管理。
- 共享材料为 UTF-8 文本快照，没有目录挂载、PDF/Word 解析或自动文件同步。UI 仅展示最近 1000 条共享消息；导出包含所选任务全部消息。
- 当前只开放通信和共享材料读取，没有代码修改、shell、外部搜索、全局扩展或通用授权面板。
- 数据库幂等不能保证外部执行 exactly-once。超时/断线/重启中的未知执行显式保留，人核对后才能解除该会话的阻塞，旧消息不会自动重发。
- 没有会话删除、备份与保留策略 UI，也没有跨设备、多个 Owner 或公网服务。
- `.noah` 中保存本地任务、材料和原生会话记录；模型推理仍发往配置的 URL。本地可见和保存不等于离线推理。
- 不同供应商可能对 Responses 等协议的字段支持不同。此次 DeepSeek 成功不能替代默认 Grok 模型服务恢复后的验证，也不意味着其他 backend 都已实测。

下一步应按实际试用补产品功能和失败恢复体验，再决定是否开放编码工具、扩展身份或恢复 Codex 排期。持续协作的收益需要真实任务评估，不能只用通信成功率说明。
