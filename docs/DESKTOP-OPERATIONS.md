# Noah 桌面通知与本机安装

适用版本：0.4.1。这里记录桌面层已经实现的行为与仍未具备的发行条件。

0.4.1 修复了后台先退出时受管子进程可能残留的问题：桌面仍清理自身创建的独立进程组，不终止原生外部会话。启动连接失败提供重连；创建和继续协作支持持久操作去重。完整审计、关键检查及本轮真实桌面结果见 [工程审计](ENGINEERING-AUDIT-2026-10-03.md)。下文保留 0.4 的通知与安装历史证据，不视为本轮重新执行。

## 需要人介入时再提醒

系统通知默认关闭。开启后，Noah 只为需要决定、执行失败、结果待核对、结论提案这四类事件发送固定文案。通知不显示讨论标题、消息正文、私有输出、路径或凭据。

前台正在使用 Noah 时不另弹系统通知。关闭窗口会隐藏窗口并保留后台订阅；选择「退出 Noah」或按 `⌘Q` 才会停止受管服务。通知点击会重新显示窗口并定位到对应讨论。原生进程的模型权限不受通知开关影响。

事件的去重记录保存在 Noah 用户数据目录的 `notifications.json`，只包含哈希标识、讨论标识和开关状态。禁用通知期间以及前台已经观察到的事件也会记录；打开开关不会补弹旧事件。系统投递失败不会在每次刷新时反复尝试。

macOS 是否真正显示通知还取决于系统设置和应用签名。[Electron 官方说明](https://www.electronjs.org/docs/latest/api/notification)要求 macOS 通知来自已签名应用。`Notification.isSupported()` 仅说明平台能力，不能证明用户授权或实际投递。程序区分 `shown`、`failed` 与未收到系统结果的 `submitted`；本轮实际应用已取得一次 `shown` 回执，但通知中心的可见内容、点击与冷启动尚未实测通过。

可在“待处理”中点击“发送测试提醒”，先检查一次系统显示。它使用明确的测试标题和固定文案，允许在前台或长期开关关闭时由你主动发送；不改变该开关、写入讨论、生成待处理事项或启动 Agent。反馈区区分系统显示回执、仅提交未确认、不支持和失败。同一次尚未返回的点击会合并；有选中的讨论时，点击通知回到该讨论，否则只显示 Noah 窗口。测试通知不进入持久事件账本，也不承诺退出应用后的测试通知恢复。

真实事项的通知支持 macOS 冷启动目标解析：只接受系统默认点击动作且标识能在已记录通知中匹配，不从未知标识推测讨论。主窗口会等待启动时的讨论/草稿恢复后再定位，避免上次选择覆盖通知目标。解析与等待逻辑的自检不等于已完成通知中心冷启动实测。

### 前端接口

`window.noahDesktop` 仅向受信任的主窗口暴露这些接口：

```js
await noahDesktop.notificationSettings(); // { enabled, supported }
await noahDesktop.setNotificationsEnabled(true);
await noahDesktop.testNotification('<UUID>'); // 一次性测试；也可传 null，仅返回 Noah
await noahDesktop.notifyActionable({
  id: 'human:<stable-item-id>',
  kind: 'human_input', // human_input | failed | uncertain | proposal
  conversationId: '<UUID>',
});
const unsubscribe = noahDesktop.onOpenConversation(conversationId => {});
await noahDesktop.releaseInfo();
```

事件必须且只能包含 `id`、`kind`、`conversationId`。`id` 最长 160 个字母、数字、下划线、连字符或冒号。前端按事项的一次出现周期生成 `attention:<UUID>`，持续刷新不另发；事项恢复后再次发生才生成新事件。初始加载已有事项静默，关闭通知或前台观察过的事项不会因开启通知或进入后台而补弹。主进程验证字段后生成系统文案。

## 窗口与版本

macOS 侧栏使用原生 sidebar vibrancy，正文画布保持实色。Noah 的浅色、深色和跟随系统偏好同时作用于内容与原生材质；系统启用减少透明度时改为实色，变化后自动同步。该行为不更改 macOS 全局偏好，其他平台和开发网页保持实色回退。顶部使用真实窗口控制与拖动区域；新建讨论面板的操作栏固定，内容可独立滚动。

「窗口 → 紧凑窗口」（`⌘⌥1`）将真实应用窗口设为 `920×680`，适合并排查看其他 harness。「默认窗口」（`⌘⌥2`）请求 `1320×860`，超出可用屏幕时按屏幕范围缩小，本机实际为 `1320×822`。窗口尺寸会保存，不以网页缩放伪装窗口尺寸。

「帮助 → 版本与发行状态」显示实际版本、平台、架构和签名身份检查结果，并明确当前缺少公证与自动更新。通知开关不会触发发行、安装或系统权限升级。

## 本机安装与回退

安装工具默认只预览，也不会自动退出应用、写入 `/Applications`、改写模型配置或处理数据库。

```sh
# 检查产物的实际签名完整性，并列出发行缺项
node scripts/check-release.cjs

# 预览安装到当前用户的 ~/Applications/Noah.app
node scripts/install-mac.cjs

# 明确执行前先退出源应用和目标应用
node scripts/install-mac.cjs --apply
```

可以通过 `--source /path/Noah.app` 和 `--destination /path/Noah.app` 指定应用路径。工具检查 Noah 的 bundle ID 与包名称，执行前检查源/目标进程，并在复制后验证签名。它不会用 Noah 覆盖其他应用。

替换现有应用前，旧应用会移入目标目录下的 `.noah-install-backups/<时间与标识>/previous-Noah.app`。成功后返回 `receiptPath`。按该记录回退：

```sh
# 先预览，不更改应用
node scripts/install-mac.cjs --rollback /absolute/path/receipt.json

# 明确执行回退
node scripts/install-mac.cjs --rollback /absolute/path/receipt.json --apply
```

回退保留被替换的新版本副本，首次安装的回退会将应用移入备份目录。安装和回退均不触碰用户数据。**应用回退不等于数据库回退**；在旧版中打开新版写入的数据前，需要确认该版本的数据库兼容性。

本轮只对现有产物执行了只读检查和安装预览，未向用户的 Applications 目录实际安装。

## 正式发行仍需提供的条件

- Developer ID Application 身份与对应签名能力；当前产物为 ad-hoc 本机签名。
- Apple 公证凭据、启用 hardened runtime 的配置及相关验收。
- 用户确认的更新托管地址、签名更新产物和升级/回退策略。

没有这些条件时，`publicReleaseReady` 明确为 `false`。本机签名完整性通过只说明当前包未被破坏，不代表已公证、可自动更新或已满足公开发行条件。
