# Noah v0.4：从可通信到可持续协作

日期：2026-10-03。状态：本地 v0.4 已交付；原 TUI 接入仍为部分验收，历史 Goal 收尾状态见 §6.13。本文件保留当时执行过程；后续 0.4.1 审计与修复见 [软件工程审计](ENGINEERING-AUDIT-2026-10-03.md)。前置基线：本地 v0.3。

本文件是本轮 Goal 的执行合同，承接 [逐项竞品研究](COMPETITIVE-RESEARCH.md) 和 [成熟度总 Spec](PRODUCT-MATURITY-SPEC.md)。原文中的“未完成”是 v0.3 的历史基线；本轮实际完成状态以本文最后的验收记录为准。

## 1. 差距的含义与取舍

Noah 已能让独立 Grok / pi 成员通过本地账本通信。离可以每天使用的产品，主要差距在工作连续性：讨论开始后如何邀请另一位成员、保留更新过的依据、发现需要人介入的问题，以及把原工作会话接进来。优先解决这些问题，才能让通信成为工作流的一部分。

| 差距 | 可学习的产品机制 | 现有问题与具体改进 | 本轮边界 |
| --- | --- | --- | --- |
| N01/N04 成员生命周期 | AionUi Team 的成员调整 | 创建后也能邀请新成员、撤销其后续参与；加入时明确是否分享此前完整公开对话 | 不复制 Leader 制度；退出不删除历史、不杀外部进程 |
| N14 资料与讨论生命周期 | Superset 的持久工作区、MCP Agent Mail 的可追溯资料 | 资料更新产生新 revision；旧 ID/hash 仍可读。归档从日常列表收起，仍可检索、导出和恢复 | 不扫描项目全部文件；恢复后保持暂停 |
| N15 Grok 原会话 | hcom 的原生 hooks / monitor 路径 | 当前 Grok 版本的真实 session 身份、原生通知及全文读取需要单独验证 | 无法保证任意 PID 热附加；不将 Grok 的通知称为 pi 的内存观察回执 |
| N19 待处理事项 | Superset 的会话状态和桌面通知 | 把待你决定、失败、待核对、原会话断开及新提议集中呈现，点击进入具体动作 | 空闲不通知；通知默认关闭，不包含正文或目录 |
| N20 可审阅结果 | ensemble 的显式完成信号、Conductor 的结果审阅 | 把结论、异议和未决问题做成有作者、依据与版本的数据，允许 owner 确认或重开 | 某条提议被确认不等于全员共识或自动结束讨论 |
| N21 多讨论规模 | Agent Relay 的消息/生命周期分层 | 按讨论轮转，限制单次状态读取负载，长历史按稳定游标取回 | 并发限流不等于限制讨论总次数 |
| N22 文件协作冲突 | MCP Agent Mail 的 advisory lease | 用户显式授权一个项目目录，成员自愿声明将修改哪些相对路径；重叠意图可见 | 这是提示性记录，不是文件锁、工具权限或安全沙箱 |
| N16 本机交付 | Superset / Conductor 的版本和安装入口 | 可核对版本、构建及发行条件；真实紧凑窗口验收；交付新的 macOS app | Developer ID、公证、更新托管依赖外部身份与服务，不伪造成功 |
| N11 可选输入预算 | 通信层与运行层分开计量 | owner 可选限制 Noah 为一场讨论新增输入的累计字节，超额暂停等待调整 | 默认无上限，不截断正文，不把字节叫 token 或模型完整上下文 |

竞品能力依据为公开官方文档，未安装这些产品进行比较测试。链接与证据范围见研究文档；功能相似不意味着成熟度相同。N17 多用户远程身份、N18 云端执行和完整 IDE 仍不属于本地单用户通信产品的本轮目标。

## 2. 不变的产品约束

1. 独立 Agent 平等交流，不增加隐藏领导模型。Codex 接入继续暂缓。
2. 默认完整分享公开讨论。私有思考、工具输出与未选择的本地文件不自动共享。
3. 新讨论默认无总次数、总时长、总输入字节上限；owner 显式设置的旧上限完整保留。
4. 打开软件、升级、恢复归档都不自动继续推理。队列空只意味着空闲。
5. 原会话保持原模型、工具和审批；原 harness 是其会话历史的唯一写入者。
6. 持久消息、接口返回、内存观察、完整读取和处理结束分别记录。未知执行不自动重试。
7. 本轮沿用仓库级 macos-design / Impeccable、官方 harness 图标与已选定的帆船 Logo。新功能遵循现有浅深主题与桌面交互，不另起视觉风格。

## 3. 用户流程

### 3.1 邀请与退出

讨论详情的“管理成员”列出当前成员及来源。邀请时选择新建 Grok/pi 或已连接工作会话，填写显示名；“分享此前公开对话”默认选中。分享以历史全文形成被动投递，不因为加入就启动模型。取消勾选只停止自动补送旧消息；当前成员仍可主动读取同讨论的公开历史，不能把它当成访问隔离开关。

移除后，该身份仍在旧发言和投递中保留。后续消息不再投递给它，旧凭据不能继续以该成员身份操作本讨论。未开始的队列取消；已启动原生处理保留真实状态，不伪称可以撤回。用户可以继续在原 harness 工作。

### 3.2 资料更新与归档

资料面板默认展示每个资料族的最新版本，可在预览中切换旧版本；新上传内容不会覆盖过去引用。UI 显示版本、快照 ID/hash。过时版本不能作为更新基线覆盖最新版本。

归档先停止新派发，保留消息、资料、结果和运行记录；不删除任何原生会话。列表可切换“进行中 / 已归档”。恢复只解除归档标记并保持暂停，是否继续由用户决定。

### 3.3 提议、依据与决定

讨论详情可以查看“结论与问题”。三类记录为结论、异议、未决问题。人或 Agent 提议时必须引用同一讨论至少一条共享消息。创建者只可修订自己的立场；其他成员或 owner 应另提观点，不能改写别人的文字。

每次修订产生新版本并回到“待确认”；owner 的确认或重开记录保留，且绑定具体版本。用户可以从依据定位原消息。结果导出保留所有版本和决定，不能仅保留最后一段文字而隐藏异议。

### 3.4 待处理中心与系统提醒

侧栏“待处理”聚合需要动作的事项，显示所在讨论、状态原因和动作。来源为数据库或已知连接状态，不通过另一个模型判断是否完成。原生不确定执行引导到核对入口，不提供会重复执行的盲重试。

系统提醒默认关闭，开启后只传事件 ID、类别、讨论 ID 给桌面主进程。标题/正文由本机固定模板生成，避免泄漏对话或目录。重复事件、普通心跳、前台已经看到的事项不反复弹出。点击聚焦窗口并定位讨论。系统未确认显示时 UI 不声称送达。

### 3.5 项目授权与写入意图

owner 在当前讨论显式登记一个存在的本机目录，并明确它的路径将分享给参与者。这只授权 Noah 记录目录与意图，不赋予 managed Agent 文件读写能力，也不变更原生工具权限。

成员用 `noah_declare_work` 声明相对路径、说明和有效期；声明及重叠路径在详情中呈现。`noah_release_work` 或到期解除提示，撤销目录授权停止新声明。包含父子路径的两条有效写入意图视为可能冲突，由参与者或用户处理；Noah 不据此强制阻断文件操作。当前检测同一讨论中的词法路径重叠，不保证发现符号链接别名或跨讨论冲突。列表及导出包含全部有效意图与最近 300 条历史意图，不能称为无限期完整文件审计。

## 4. 数据与 API 合同

### 4.1 Schema v5

- conversations：`archived_at`、`context_budget_bytes`（默认 null）、`context_used_bytes`。
- sessions：`joined_at`、`removed_at`；常规调度只取未移除成员，历史查询保留所有身份。
- materials：`family_id`、`revision`、`previous_id`、`created_at`；内容快照不可变。
- outcomes / outcome_revisions：稳定 ID、作者、种类、当前版本、正文、依据消息及 owner 决定。
- context_charges：以 `(conversation_id, charge_key)` 保证原生读取重试不重复扣预算。
- 项目授权及工作意图单独存表，引用讨论和成员；不在项目目录创建锁文件或扫描文件内容。

迁移前对已有数据库创建一致性备份，保留旧暂停、额度、消息和草稿。失败不能留下半升级状态。恢复旧版本数据需要明确流程，不能直接让旧程序写入新版结构。

### 4.2 Owner 路由

| 路由 | 输入 / 行为 |
| --- | --- |
| POST `/api/conversations/:id/control` | archive / restore；其余原控制兼容 |
| POST `.../context-budget` | `{contextBudgetBytes: 正整数或 null}`；调整后不自动恢复讨论 |
| POST `.../participants` | `{participant, shareHistory, modelAlias?}`；原会话绑定须可用 |
| POST `.../participants/:agent/remove` | 撤销后续成员参与，保留历史 |
| POST `.../materials/:materialId/revisions` | `{name, content}`；需基于当前最新版本 |
| POST `.../outcomes` | `{kind,title,content,evidenceMessageIds,clientKey?}` |
| POST `.../outcomes/:outcomeId/revisions` | `{title,content,evidenceMessageIds,expectedRevision}` |
| POST `.../outcomes/:outcomeId/decision` | `{decision:'confirmed'|'reopened',expectedRevision}` |
| 项目授权与工作意图 | owner 可授予/撤销目录，参与者只能声明和释放自己的意图 |

所有 ID 和跨讨论引用由服务端验证；UI 的隐藏按钮不承担权限控制。

### 4.3 输入预算

`reserveContextBytes(conversationId, chargeKey, bytes)` 原子校验并预留 Noah 新增输入。相同 key 与字节数重试幂等；内容计量冲突拒绝。超额保存暂停状态，不扣额度、不截断正文、不新增模型请求。managed 未提交的运行恢复队列，不计 prompt start。

预算范围是 Noah 新增的受管输入及原生桥接正文/通知，不包括用户在原 harness 里的既有上下文，也不是供应商实测 token。原生预留和真正观察到的正文计量独立显示；ACK 丢失不能把一次输入重复计为两次。手动读材料或原生工具自身的 token 不在该预算里，界面必须说明。

### 4.4 Grok 原生接入

本机 Grok 1.0.41 有 hooks 与 monitor 入口，但尚未证实任意正在运行的会话可以无准备热接入。实现采用项目级 hooks 文件与一次性加入授权，原 Agent 在已有会话内执行连接，真实 session ID 来自原生 hook。不得从 transcript 另开 writer 或覆盖模型配置。

Grok 的能力标签是“实验性：原生通知 + 主动分页读取完整正文”；它不支持 pi 相同的被动追加观察回执。监控通知合并提示待处理批次，正文分段完整读取，所有分段有顺序游标，不默默丢弃超长正文。监控心跳只证明 monitor 在线，不证明原 Grok 空闲；`monitor_notified` 与 `agent_reported` 也不能称为模型已读或内存观察。

本地 HTTP/Node CLI 的模拟 hook 检查已通过。2026-10-03 用户批准后，真实 Grok 1.0.41 ACP 在临时 config hooks 加载方式下完成注册、原生 monitor 自动通知、全文读取及显式回复，使用临时 HOME、本地假模型及假密钥。session plugin 入口仍未触发观察器；本次 config 对照未修改用户配置，也不代表 TUI 中途加入已验收。详见 [接入说明](GROK-NATIVE-SETUP.md) 与 [原生诊断记录](GROK-NATIVE-PROBE-AUDIT.md)。
