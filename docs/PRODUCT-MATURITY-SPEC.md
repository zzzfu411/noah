# Noah 产品差距与工程实施 Spec

版本：0.4，2026-10-03 更新。第 1–9 节保留最初差距分析与 v0.3 验收基线；当前实施增量见第 10 节及 [v0.4 执行 Spec](GOAL-V0.4-SPEC.md)。历史的“未实现”不能作为当前功能状态。

这份 Spec 比较 Noah 与 AionUi、hcom、Agent Relay、MCP Agent Mail、AgentLink、ensemble、Superset 和 Conductor，规定可借鉴的能力、实现顺序及验收方式。目标是让独立的本地 Agent 会话参加同一场讨论，并让用户理解连接、投递和运行的实际状态。竞品官方功能描述不等于经过本项目实测；AgentLink、ensemble 仍明确标注实验性，不能把所有比较对象称为成熟产品。逐项证据见 [竞品研究](COMPETITIVE-RESEARCH.md)。

## 1 当前差距判断

Noah 已有独立桌面应用、官方 Harness 标识、完整消息渲染、安装发现、Grok 和 pi 的真实定向通信、SQLite 持久化、暂停与停止、不确定执行处理、草稿恢复以及 Markdown 导出。最大的差距在会话模型、原生会话接入和日常使用闭环，而不只是界面美观。

实施前代码中的具体约束：`sessions` 主键为 `(conversation_id, agent)`，`agent` 仅允许 `grok/pi`；`deliveries.message_id UNIQUE` 只允许一个收件者；Engine 每条消息启动一次，并反复附加完整规则；界面固定两位参与者。共享消息虽可主动读取，却没有按成员自动同步的完整投递账本。安装发现没有连接任何外部工作进程。全局 snapshot 只显示最近 1000 条消息，标题搜索不检索正文。

“平等讨论”是默认协作方式，不限制 Agent 在具体任务中自愿分工。Noah 不创建一个隐藏的 Leader 模型来替用户决定所有路由。

## 2 范围与用户流程

### 2.1 打开即知道能做什么

本机 Agents 分别展示已检测的程序与真正连接的原生会话。没有 Grok 时，用户仍可选择多个内置 pi 会话；没有新建模型配置但已有可用的原 pi 会话时，可以创建只包含外部会话的讨论。检测不会读取所有私有对话，不执行未知路径下的程序。

连接现有 pi 的首次流程：在 Noah 生成短期加入文件；按界面说明加载仓库分发的扩展；在原 pi 中执行连接命令。扩展完成一次明确注册后才进入可选列表。加载扩展本身不改变模型、工具权限或自动开始讨论；所有后续推理仍遵循原 harness 设置。

### 2.2 创建讨论

用户输入主题，添加所需成员，每位成员显示名称、harness、来源。受管新会话使用用户选择的 Grok 模型配置；外部会话沿用自己的模型。默认自主讨论、无总次数/时长上限；可选限制保留。创建空讨论不调用模型。

成员 ID 在讨论中不可变、不可伪造；标签仅用于显示。可以有“pi 架构讨论”“pi 实现复核”等相同 harness 成员。界面提供“全部参与者”或具体成员收件目标。广播只写一份公开消息，每位目标独立处理。

### 2.3 阅读、回复与干预

正文默认全部公开给本讨论成员；收件目标决定本轮要处理的人。每条消息可展开逐人投递状态，回复指向稳定 message ID。人类可以暂停新派发、请求停止 Noah 管理的运行、结束不确定投递；这些动作不宣称能终止外部原生工作进程。

详情显示成员来源、连接状态和实际计量。标题搜索继续可用；新增全文搜索只搜索共享正文，可回到消息位置。长讨论可以加载早期消息，不能因为其他讨论增多而失去可见历史。

## 3 数据与兼容性

保留现有表名和旧 API 默认，扩展 `sessions.agent` 为 participant ID，并新增 `harness`、`label`、`mode`、`binding_id`。旧 `grok/pi` 行迁移为同名受管成员；旧草稿的 recipient 仍有效。原有暂停状态、限额、消息 ID、client key、原生 ID、私有输出和资料保持不变。

`deliveries` 改为 `(message_id, agent)` 唯一。新增关注标记和批次关联；一个 batch 对应一次 managed prompt，但每条投递仍保留独立状态。迁移前为非空旧 SQLite 生成一致性备份，迁移事务失败不留下半升级状态，备份不得覆盖已有文件。

外部绑定独立于讨论成员保存。一个绑定可以参加多场讨论，但唤醒锁按真实 binding 设置。既有原生历史唯一 writer 始终是原 harness。Noah 仅读写自己的账本和扩展状态。

## 4 通信契约

### 4.1 公开消息

发送者来自服务绑定凭证，不接受模型自报身份。收件人只能是本讨论成员、`human` 或 `all`。回复必须属于本讨论。幂等键重试原消息返回原 ID，键冲突不覆盖旧内容。

公开消息先提交数据库，再返回 `persisted`；发送工具不等待对方模型。向 human 报告也进入公开讨论，旁观成员可以收到，但不因一份报告自动启动推理。私有模型输出、思考和本机文件不会自动共享。

### 4.2 完整正文与唤醒

所有成员有各自的待同步公开消息。managed harness 没有已验证的被动追加接口时，旁观消息保持排队，在下一次定向运行前合并进输入，并在 UI 说明“等待下一次定向处理”。不为了同步旁观正文额外制造模型调用。

pi 扩展通过公开 custom message API 被动追加完整正文。API 返回 void 只代表提交动作，不能命名为已落盘。扩展只在原会话只读 entries 中核对 Noah 标记、正文 hash、binding 与序号；匹配后回报 `transcript_observed`。这不保证永久保留在模型窗口，也不代表已读或推理完成。

定向唤醒需要独立授权记录。先被动追加，再由一次合并唤醒引导成员处理已送达的问题；重复网络请求不能产生重复启动。未知执行必须保留待核对状态，不自动重跑。无定向消息时只做本地连接维护，模型启动次数应为 0。

### 4.3 外部连接

所有接口绑定 loopback，并继续校验 Host 和 Origin。owner token 只用于桌面管理；生成的短期一次性 join token 不具有 owner 权限。注册后 credential 限于绑定会话。租约失效、断连、切换 session、用户撤销立即阻止旧 generation 继续使用。

默认注册只上报原生 ID、harness/version、可选标题/项目、忙闲状态及 capability。私有历史对账在扩展进程内完成，不上传用户全部对话。退出讨论/Noah 退出不能杀掉原会话；Noah 重启后不自动恢复推理。

## 5 搜索、导出与诊断

正文搜索由 owner 请求，SQLite 查询使用参数绑定，搜索词中的 `%`、`_` 等按字面处理。结果包含讨论标题、消息作者、时间、定位 ID 与片段；返回数量有边界，并说明截断。没有命中时显示可恢复的空状态。

分页以不可变 seq 为游标，升序展示，同一消息只渲染一次。定位搜索结果时允许请求目标附近历史。网络失败保留当前已加载消息并给出重试。

JSON 导出至少含 schemaVersion、导出时间、discussion、participants、完整公开 messages、逐人 deliveries、显式 materials；排除凭证、配置密钥、native_file、私有 runs.output 和未共享本机数据。Markdown 继续可读。导出不能被描述为可直接恢复整个原生环境的备份。

诊断默认只读：返回 runtime 配置存在性、bridge 在线/离线、队列数量、不确定投递数量、最近错误及恢复建议，不启动 Agent。持久消息、观察到原生上下文、运行结束和任务完成必须分别陈述。

## 6 度量与性能

- managed run 记录实际提交文本的 UTF-8 `input_bytes`、公开正文 `message_bytes`、`message_count`、`prompt_starts`。模型 token 仅展示 harness 返回值；缺失即未知。
- 外部追加计量与外部 wake 独立记录，不能合并为 managed prompt 字节，也不能把正文字符除以 4 当实测 token。
- 10 条排队定向消息在一次调度中可以合并；不因状态心跳、ACK 或 SSE 更新调用模型。
- 一次模型请求可能携带原会话既有上下文；Noah 的“新增字节”不能冒充总成本或节省比例。
- UI 在 920×680 和常用桌面尺寸可完成创建、连接、检索、暂停；浅深主题保持正文对比度及键盘可达。
- 本轮不引入隐藏总量上限或语义循环检测。大输入硬限制如果将来引入，必须明确报错和可恢复，不能静默截断。
