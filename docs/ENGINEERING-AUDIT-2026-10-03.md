# Noah 软件工程审计与可用性修复 Spec

日期：2026-10-03。交付版本：0.4.1，Apple Silicon 本机桌面包已完成检查并打开。范围：本机单用户 macOS 应用、Grok/pi 通信、数据恢复及日常交互。代码、隔离验证、真实桌面和历史原生证据分别记录；本次不把已有测试通过数当作新验收。

## 1. 判断

Noah 已有可继续建设的通信核心，不需要推倒重写。SQLite 消息账本、独立 Agent 身份、原进程扩展、明确的权限边界和桌面托管方式，符合当前本地产品的规模与目标。

主要不足在异常路径与接入闭环：先前部分失败被错误标成完成，部分未提交消息无法恢复，用户操作的重试合同不完整。它们比继续增加视觉装饰或新功能更影响长期使用。本轮先修正这些真实可触发问题。

“真正可用”分两个层次：已配置 Grok 模型服务的用户，可在 Noah 内创建独立 Grok/pi 讨论；把任意正在运行的原会话无缝接入，仍受 harness 接口和原 TUI 验收限制。受管新会话当前只有通信和显式资料工具，不是完整编码环境。原会话才保留既有编码工具与审批。

## 2. 审计方法与判定标准

并行审查核心存储/调度、原生集成、前端交互；主线程复核服务生命周期、接口边界、文档和桌面交付。审查现有源码、锁定的依赖实现及验证记录，先确认触发条件再改代码。

优先级：P1 为会误导执行判断、遗失恢复机会或危及数据/进程归属的问题；P2 为可绕过但影响日常工作的交互和运维缺口；P3 为后续可维护性、规模和发行建设。本轮未发现足以判为 P0 的证据，但这不等于穷尽所有缺陷。

每组只补 2–5 个关键场景；跨层完成后做一次受影响模块整合、类型检查和现有 UI 检查。使用临时数据库、假凭据和本地模型替身，不对真实讨论发消息或自动恢复。真实应用检查限于新增入口、浅深主题、920×680 和旧状态保留。

## 3. 实现成功之处

| 维度 | 已成功的工程选择 | 实际价值及应保持的边界 |
| --- | --- | --- |
| 架构 | Electron 托管本机服务；TypeScript 模块化单体 | 无需用户手动保持终端服务；当前无需引入微服务、云端账号或第二套调度器 |
| 通信 | SQLite 持久收件箱、每接收者独立投递、稳定消息 ID/发送 key | 双向发信平等，界面重连不等于重新执行；投递状态与公开发言分开 |
| 上下文 | 完整公开正文按消息增量提供，资料引用带 ID/hash | 不复制私有原会话；原用户选择的全文共享被保留，但全文仍会消耗上下文 |
| 原生接入 | pi 扩展在原进程内；Grok 使用 hook/monitor/CLI | 原 harness 保持唯一历史写入者，不把磁盘 transcript 当作在线会话 |
| 权限 | owner、managed 工具凭据、native 绑定凭据各自校验；租约与 generation | Agent 不能冒充 owner；安装发现不被当作可用连接或工具权限 |
| 数据 | WAL、事务、迁移前一致性备份、不可变资料 revision、版本化提议 | 讨论归档不删除证据，旧资料引用仍可读，确认结论绑定具体版本 |
| 调度 | 讨论间轮转、受管并发 2、成员串行 | 并发控制与讨论总次数分开；默认自主往返，原有暂停及可选限制保留 |
| 恢复 | 未知执行不自动重放；重启和恢复归档保持暂停 | 不因重开应用意外再次调用模型；人能核对后继续 |
| 桌面 | 原生窗口控制、侧栏材质、系统外观和减少透明度回退 | 已建立一致的桌面视觉基础；本轮沿用设计，不重做品牌和布局 |
| 可观测性 | 待处理中心、回执、资料/历史分页、诊断与导出 | 用户可定位故障和证据；空闲不冒充共识，系统通知默认关闭且无讨论正文 |

## 4. 已确认问题与修复合同

### A01 / P1：连接失败使尚未发送的问题失去恢复机会

触发：适配器初始化、配置读取或握手失败，尚未 claim/调用模型。原实现把最初投递置为 failed；用户修复连接后点击继续，也不会再领取这条消息。

合同：未领取的消息保持 queued，显示明确连接错误并暂停；只有用户继续后才重新接入。已提交且结果未知仍为 uncertain，不自动重放。异步失败不能覆盖已移除成员的 cancelled。

实现：`src/engine.ts`。关键检查：首次启动失败后保留正文与零 prompt；修复后显式继续仅送一次；未知超时不自动重试。

### A02 / P1：pi 取消或模型错误被显示为完成

触发：pi SDK 的 `agent_settled` 也会在 abort/error 后发出，原客户端无条件向 broker 提交 settled。

合同：在原进程内核对当前 wake 之后的新 assistant 终态；有匹配的正常终态才能确认处理结束。取消、错误或缺乏完成证据进入 uncertain，不再次自动启动。仅传状态，私有 assistant 正文不离开进程。处理结束也不代表观点正确、任务完成或全员共识。

实现：`src/native-bridge-client.ts`。以真实 pi SDK + 内存模型替身复现 error/aborted/stop；旧成功回合不能替代当前回合的完成证据。

### A03 / P1：pi 断线后唤醒与投递状态不一致

触发：租约过期、重启、撤销等把 wake 改为 uncertain，原 delivery 仍为 transcript_observed，界面可能给出矛盾信息。

合同：同一事务同步 wake 与关联 delivery；保留全文和已经存在的观察证据，owner 核对后结束旧投递，不自动重放。已完成/已取消投递保持终态。

实现：`src/native-bridge.ts`。覆盖连接过期、撤销、重启、关闭与上下文暂停。

### A04 / P1：后台退出后受管子进程可能存活

触发：后台服务崩溃或先退出，桌面 `stop()` 因 child 已退出而提前返回；同一进程组内的受管子进程不再被清理。

合同：退出后也清理本桌面创建的独立进程组，先正常终止，短暂等待后强制结束残留；仅操作该组，不扫描/终止用户的外部 harness。请求退出不显示崩溃提示，异常退出则清理后进入恢复提示。

实现：`desktop/backend.cjs`。隔离真实 Node 进程树检查崩溃与正常退出两条路径，同时验证另一个独立进程仍存活。

### A05 / P1：旧应用能够写入更高版本数据库

触发：`user_version` 高于当前支持版本时，Store 仍执行 schema/data 写入和恢复，应用回退可能破坏新版数据。

合同：首次 schema/data 写入前拒绝更高版本，提示更新应用，关闭数据库句柄；初始化失败清除本次启动锁。不能静默降级、删除或恢复成旧备份。

实现：`src/store.ts`、`src/server.ts`。检查未来版本文件逐字节不变，并确认在同一进程重试仍得到正确版本错误，而非遗留锁错误。

### A06 / P2：检测出的路径与真正启动使用的路径不同

触发：`NOAH_GROK_CONFIG` 或 `NOAH_GROK_BIN` 包含 `~/`；发现页展开路径成功，配置读取或子进程却使用未展开原字符串。

合同：发现、模型列表、配置读取和受管启动使用一致解析路径。无效显式可执行文件不得悄悄改用另一份安装。

实现：`src/config.ts`、`src/adapters.ts`。临时配置与假 ACP 可执行文件完成两项检查，不启动真实 Grok 或模型。

### A07 / P2：异步表单提交覆盖后来操作

触发：创建期间关闭并重新打开表单，旧响应关闭新窗口或清空新主题；恢复协作快速重复点击会重复提交；新增功能弹窗未纳入全局快捷键关闭流程。

合同：提交使用固定 payload 与弹窗代次，旧响应不夺走新选择/草稿；恢复提交按讨论锁定，错误原地可见。全局新建/搜索/聚焦动作正确关闭当前 modal，过期读取结果不覆盖新内容。

实现：`public/app.js`、`public/maturity.js`、`public/index.html`。保留当前视觉样式、原有消息草稿与结论版本语义。

### A08 / P2：创建/继续操作缺少持久重试幂等

触发：业务已提交但 HTTP 响应丢失。仅禁用按钮无法阻止用户重试时重复创建，或为已有讨论再次增加额度。

合同：创建和 resume 支持可选 `clientKey`，业务写入与结果记录位于同一事务。同 scope、同 key、同 payload 返回原结果；同 key 不同 payload 拒绝。前端未确认成功的相同提交沿用 key，内容变化或明确新操作重新编号。旧无 key 客户端继续兼容，Agent 的未知推理仍不自动重放。

验收：创建/恢复响应丢失重试、跨服务重启持久去重、冲突拒绝、旧客户端语义以及前端 key 生命周期。

### A09 / P2：首次启动和创建被阻挡时缺少下一步

触发：配置缺失或原会话离线时只见不可用的创建按钮；首次配对/读取失败后，没有直接重新连接入口；新会话的工具范围也容易被误解。

合同：按实际原因说明并提供只读诊断入口，返回时保留主题；启动失败显示重新连接，重试不得重复建立 SSE/事件监听或覆盖草稿。明确新受管成员的通信/资料工具范围，引导已有编码工作选择原会话。

## 5. 本轮不应假装已经解决的差距

| 优先级 | 差距与影响 | 下一步与验收要求 |
| --- | --- | --- |
| P1 接入门槛 | Grok 原 TUI 热加载、原审批、shared leader 单会话结束未完整验收 | 使用允许的真实原生入口验证唯一 writer、原工作继续和单会话退出；原入口保持实验性。此前电脑控制工具禁止 Ghostty，不绕过 |
| P2 原 pi 场景 | SDK/扩展链路成功不等于实际 TUI 审批、长任务和用户操作均成功 | 实际 TUI 中加载、授权、忙时消息、取消、断开后原任务继续，单独记录；不把本轮假模型称为付费模型实测 |
| P2 即开即用 | 发现安装只验证文件存在；模型凭据/上游服务不保证可用，原会话仍需加载扩展或 hooks | 后续建立经验证的 harness 安装/接入向导；不能为了少一步操作而接管未知 PID 或打开第二 writer |
| P2 长讨论 | 受管 `claimWork` 一次合并所有积压正文；默认无字节预算时可能超过模型上下文 | 增加保留全文的分批游标策略，验证跨批顺序、待处理标记和上下文容量；不静默改成摘要或截断正文 |
| P2 规模 | 调度、快照和搜索仍有同步全量 SQLite 查询；UI 表单依赖共享可变状态 | 先用真实量级测量延迟，再加索引/增量查询及按讨论的请求状态模块；不以小 fixture 推断大数据性能 |
| P2 草稿 | 消息草稿可靠，但其他业务表单的退出恢复策略未完全统一 | 区分可恢复草稿和短期表单；明确重开/退出行为，避免自动恢复临时凭据 |
| P2 开发可追溯性 | 当前目录及父目录不是 Git 工作区，没有可用的提交/分支历史 | 后续建立本地版本控制、排除用户数据库与凭据，再接入持续检查；本轮未擅自初始化或推送远程 |
| P2 可观测性 | 私有运行输出最多保留 65,536 字符，公开消息全文独立保存 | 本轮已在面板说明输出范围；未来增加有界日志/诊断包，默认脱敏，不收集原 harness 私有历史 |
| P2 系统通知 | 已获得一次 show 回执，通知中心内容、点击及冷启动尚未实测 | 在系统 UI 可访问时完成一次完整验证，不能只凭 mock 或 Electron 回执宣称投递完成 |
| P3 分发 | 目前只有本机 ad-hoc 签名，无 Developer ID、公证或更新源 | 获取发行条件后实现签名更新与真实升级/回退。当前不能称为面向所有 Mac 用户的正式稳定发行版 |
| P3 包体/平台 | 当前 arm64 应用约 656 MiB，未验证 Intel Mac、Windows、Linux | 在当前平台稳定后按实际依赖裁剪并量化启动/内存；先保持稳定，避免盲删 SDK 依赖 |

## 6. 本轮可用性验收清单

1. **开始**：可见可用成员与模型，缺失条件有明确下一步；创建不重复，不清空后填内容。
2. **通信**：正文和成员身份持久保留；原 pi 的失败/中断不会显示成功；Grok/pi 仍可平等发信。
3. **恢复**：未提交消息可在修复后继续；未知执行不重放；相同恢复请求只生效一次。
4. **数据与退出**：拒绝更高版本数据库且不改文件；只清理 Noah 受管进程；重开仍保留原暂停讨论与草稿。
5. **桌面**：浅深主题、920×680、诊断和跨弹窗快捷键可用；交付产物与源码一致并通过本机签名检查。
